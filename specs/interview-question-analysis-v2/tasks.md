# 面试问题识别与面试官分析升级实施任务

## P0 规则与数据基础

- [x] 1. 建立面试问题分类枚举
  - `communication_check`、`condition_check`、`job_question`、`needs_context`。
  - 所有前端和后端使用同一组枚举。
  - _需求：R1、R2_

- [x] 2. 抽离沟通确认规则
  - 建立可版本化词表和规则函数。
  - 覆盖听见、信号、方便说话、稍等、录音、共享屏幕、开始等固定话术。
  - 规则命中后不得调用 AI。
  - _需求：R1_

- [x] 3. 增加问题候选标准化结构
  - 保存原句、标准化文本、说话人、时间戳、上下文、来源和分类状态。
  - 不再只依据句末问号提取问题。
  - _需求：R3、R4_

- [x] 4. 实现条件核验分类
  - 支持地点、到岗、薪资、竞业、办公方式、出差、班次。
  - 与岗位规则和 JD 建立可选关联。
  - _需求：R2、R3_

## P1 AI 边界分类与校验

- [x] 5. 实现岗位问题候选识别
  - 基于说话人、问句模式、岗位词和经历/项目/结果语义形成候选集。
  - 候选不得直接进入高频问题。
  - _需求：R3_

- [x] 6. 增加 AI 四分类调用
  - 输入当前句、前后文、岗位、JD 和岗位规则。
  - 输出严格 JSON Schema。
  - AI 只能归类实际问过的句子，不得编造问题。
  - _需求：R3、R4_

- [x] 7. 增加程序化证据校验
  - 校验 `evidenceQuote` 是否存在于转写原文。
  - 非法枚举、证据缺失或标准化问题新增事实时降级为 `needs_context`。
  - _需求：R4_

- [x] 8. 实现上下文合并和跨场次去重
  - 短句优先合并前置问题。
  - 无法合并时进入待判断。
  - 去重后保留全部来源场次。
  - _需求：R2、R3_

## P2 面试官分析和页面

- [x] 9. 增加 5 场有效转写门槛
  - 小于 5 场：只展示规则分类结果和原始问题。
  - 不输出偏好、追问方式、比率和个人评价。
  - _需求：R5_

- [x] 10. 重构“面试问题与偏好”区域
  - 分为高频岗位问题、条件核验、待判断。
  - 增加原句、场次、岗位准则和证据查看。
  - 显示已排除的沟通确认数量。
  - _需求：R6_

- [x] 11. 增加人工复核操作
  - 待判断句支持归入岗位问题、条件核验或保持待判断。
  - 人工分类写入审计和版本记录。
  - _需求：R2、R6_

- [x] 12. 重建面试官问题覆盖分析
  - 仅使用已核验的岗位问题和条件核验。
  - 所有结论显示来源场次和原句。
  - _需求：R5_

## P3 测试与上线

- [x] 14. 增加 1/2/4/5/6 场样本量测试。
- [x] 15. 增加“你好，可以听见吗？”等回归样本。
- [x] 16. 验证无岗位、JD 不匹配、多面试官和跨行问句场景。
- [x] 17. 更新接口文档、页面文案和分析说明。
- [x] 18. 通过测试后再发布前端和云函数。
