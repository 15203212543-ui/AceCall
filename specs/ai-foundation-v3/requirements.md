# AceCall AI 基础能力重构：需求规格

## 1. 目标

将 AceCall 从多个相互独立的 AI 生成点，升级为“文档解析 → 带证据事实 → 人工确认 → 岗位匹配 → 电话/面试分析 → 人工确认后输出”的可追溯招聘判断系统。

核心原则：

- 规则和文档解析负责确定性字段；模型负责语义判断和归纳；程序负责校验与状态流转；人工负责冲突裁决和最终结论。
- 模型不得凭空生成姓名、电话、邮箱、公司或其他确定性事实。
- “未提及”不得被写成“不具备”。
- 人工确认锁定的是当前值，不是阻止新事实进入系统；新文档出现不同值时必须产生冲突。
- 不自动淘汰候选人，不自动修改 Moka 阶段。

## 2. P0 现状问题

1. 批量导入的四处实现可能在匹配失败时使用 `jobs[0]`，并标记为“已分配”。
2. 候选人文档中保存完整简历文本，状态接口可能把全部正文返回前端。
3. 清洗文本覆盖原文，缺少可追溯证据基础。
4. `/api/generate`、`/api/parse-resume`、`/api/transcribe` 必须统一经过身份、租户、业务权限和限流校验。
5. 长录音仍可能走百度短语音接口，存在 60 秒/10MB 限制；异步 worker 必须上线。
6. 现有系统没有 retention 清理任务。
7. 录音前缺少告知与同意记录。

## 3. 范围

### 本期范围

- 文档原文/清洗文双版本及云存储元数据
- 候选人事实中心、证据、冲突、人工确认和版本记录
- 桌面助手与网页端共用岗位匹配判定
- 批量导入待分配修复
- API 鉴权、租户隔离、业务权限、限流和审计
- 长音频异步转写 worker
- 姓名/基础字段/经历条目/岗位口径/匹配解释
- 转写身份绑定、问答切分、电话总结和审核草稿
- 面试官客观分析（小样本保护）
- 内部访谈线索型行业情报

### 非本期范围

- 自动淘汰候选人
- 自动改变 Moka 候选人阶段
- 面试官能力排名或绩效结论
- 独立微调模型
- 未接入外部数据源前的“已验证行业情报”
- 扫描版 PDF 的完整 OCR 识别（本期只检测并提示）

## 4. 用户故事与验收标准

### R1 文档与证据

- 当用户上传简历或转写文件时，系统应将二进制文件保存到私有云存储，并在数据库保存 `storageFileId`、哈希、原文、清洗文和解析元数据。
- 当系统抽取任一事实时，事实必须包含 `sourceType`、`sourceRef`、`quote`、`confidenceBasis` 和 `verified` 状态。
- 当证据短句无法在原文或清洗文中通过程序化匹配找到时，系统必须将事实降级为 `pending`，不得写入确定性结论。

### R2 人工确认与冲突

- 当招聘人员确认姓名、岗位或事实值后，后续新文档不得覆盖当前值。
- 当新文档产生不同事实时，系统必须保留新事实并生成 `conflict`，供人工裁决。
- 当人工修改事实时，系统必须追加审计和 revision，不覆盖历史版本。

### R3 岗位匹配

- 当岗位匹配失败、必备项待核验超阈值或多个岗位满足条件时，系统必须进入“待确认/多岗位候选”，不得使用 `jobs[0]` 兜底。
- 当岗位规则变更时，历史匹配必须保留当时使用的岗位规则快照。
- 匹配结果必须逐条展示“命中、待核验、未发现、冲突”及证据。
- 分数只能作为排序展示，不得作为唯一分配或淘汰依据。

### R4 长音频与录音

- 当录音超过 60 秒或 10MB 时，系统必须进入异步转写任务，不得调用短语音接口直接失败。
- 当用户点击开始录音时，系统必须先展示告知并记录同意状态；未同意时不得启动录音。
- 当转写任务完成时，系统必须通过任务状态轮询返回最终文本、分段和说话人状态。

### R5 权限与数据保护

- 当接口请求没有有效用户身份、租户或业务权限时，系统不得返回业务数据。
- 当用户访问其他租户资源时，系统必须返回 404，不泄露资源是否存在。
- 限流必须按 `tenantId + route`，不得只按 IP。
- 到达保留期限的数据必须由定时任务删除原始文件和 PII，并保留去标识化审计记录。

### R6 分析输出

- 电话总结、审核结论和面试官分析必须引用事实中心和证据，不得直接把模型自由文本写入最终业务字段。
- 有效转写场次少于 5 场时，面试官页面只能展示客观数据和原始问题，不展示比率、改进建议或个人评价。
- Moka 备注必须先生成内部草稿，只有人工确认后才可幂等写入。

## 5. 阶段验收

- 测试集分为 dev set（15-20 份简历、8-10 份转写）和 held-out test set（累计 60 份简历、30 份转写），开发期间不得使用 held-out 调参。
- 姓名严格完全匹配准确率按 6 类边界场景分别统计，目标每类 ≥95%。
- 关键字段 100% 包含来源和证据。
- 人工确认值不会被新增文档覆盖，只产生冲突。
- `acecall_candidates` 不再保存或返回完整简历正文。
- 跨租户访问返回 404。
- 同一转写任务和同一 Moka 备注重复提交不会产生重复记录。
