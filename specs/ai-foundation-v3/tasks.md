# AceCall AI 基础能力重构：实施任务

执行规则：先完成 P0 并通过验收，再进入 P1；不要在 P0 前进行大规模页面重构或 Prompt 调优。每个任务完成后补测试和变更说明。

## P0：正确性、权限和基础设施

- [x] 1. 保留文档原文与清洗文双版本
  - 修改解析流水线，保存 `rawText`、`cleanedText`、解析版本和行号/段落映射。
  - 保持已有清洗规则，不重复实现已存在的控制字符、重复行和断行清洗。
  - 验收：同一文件可同时查看原文和清洗文；证据可在至少一个版本中定位。
  - _需求：R1_

- [x] 2. 抽取统一岗位匹配函数
  - 将网页端、`local-sync-agent`、`desktop-agent` 和云函数中的判定逻辑收敛到一个共享实现。
  - 删除所有 `jobs[0]` 兜底和无条件“已分配”。
  - 验收：匹配失败进入待分配；无关候选人不会被分配到岗位库第一项。
  - _需求：R3_

- [x] 3. 接入业务鉴权、限流与审计
  - 为 `/api/generate`、`/api/parse-resume`、`/api/transcribe` 补充统一请求上下文。
  - 按 `tenantId + route` 限流，错误响应和日志不得回显 token。
  - 验收：未登录和过期 token 被拒绝；合法桌面助手会话继续可用。
  - _需求：R5_

- [x] 4. 建立第三层业务权限
  - 实现统一资源归属校验助手，覆盖候选人、文档、岗位、转写、AI 任务和分析结果。
  - 跨租户访问返回 404。
  - _需求：R5_

- [x] 5. 将简历全文迁移到文档层
  - 新增 `acecall_documents`，二进制进入私有云存储，候选人保存 documentId/摘要。
  - `/api/state` 不再返回全量简历正文。
  - 提供历史回填脚本和兼容读取期。
  - _需求：R1、R5_

- [x] 6. 部署长音频异步 worker
  - 复用录音分片协议，打通 queued/running/succeeded/failed 状态轮询。
  - 将百度、Whisper、FunASR 封装为可替换引擎。
  - 验收：超过 60 秒/10MB 的录音可以进入异步任务并返回最终文本或明确失败原因。
  - _需求：R4_

- [x] 7. 增加录音告知与同意
  - 开始录音前展示告知；记录同意人、时间、候选人和会话。
  - 拒绝后允许手工记录，不启动录音。
  - _需求：R4、R5_

- [x] 8. 建立 dev/held-out 回归样本
  - 准备第一批 15-20 份脱敏简历、8-10 份转写，覆盖六类边界场景。
  - 单独准备最终累计 60 份简历、30 份转写的 held-out 集，开发期不得调参使用。
  - _需求：阶段验收_
